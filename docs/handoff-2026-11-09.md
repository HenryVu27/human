## Operational traps

**Pangram scans**
- Chrome: this MacBook's Chrome is not linked to Claude Code. The linked browsers are Henry's PC ("personal pc", selected by him on 11-09) and his work Mac. To change, use `switch_browser`, which puts a Connect button in each linked Chrome. `list_connected_browsers`' `isLocal` is unreliable: the "macOS" entry is the work Mac (14 cores, 3456 x 2234).
- The 127.0.0.1 token check can only pass from a browser on this Mac. Henry chose the PC himself; never use the work Mac without his say-so.
- The dashboard failed on 11-09 with "Connection problem, retrying". Its page also needs several seconds after load before login state appears. Upload all files in one call: adding a second file separately left it stuck.
- `experiments/pangram_check.py` scans through the API with per-passage flags, but Henry must run it himself. The Mnemosyne guard blocks agents from loading `.env`, correctly.

**PC jobs**
- Check Tailscale first; the PC can be on while its Tailscale is offline.
- Copy with `scp -O`; .cmd files need CRLF.
- Launch hidden through a `.ps1` with `Start-Process -WindowStyle Hidden` (`experiments/gpu/p2e.cmd` pattern). A visible console was closed and killed a run.
- Henry games on this PC. Look for game processes and GPU memory before launching. Never start beside a game without his say-so, and never close his game.
- A killed run leaves a stale `C:\gpu-lock`. Release it only if the owner line is yours and no Python is running.

**Watchers**
- Background watchers die when the session restarts; a job can finish unread.
- In zsh, `echo` of Windows logs mangles backslashes into NUL bytes and `grep` then misses matches. Use `printf '%s\n'`, `tr -d '\000'` and `grep -a`.
- Watch for silent death too, not only done or failed. See the P2e watcher pattern: no Python for 12 minutes, or no PC for 30.

**Method**
- `humanizer.llm` keeps at most 4 workers on Henry's shared Claude account.
- Short or number-heavy text does not fit the rewriter; it was trained on 600 to 1,000-word sections.
